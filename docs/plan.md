# Oasis Auto Spa — Dashboard + Backend, built from the three Claude Design prototypes

## Context
Franco (unielogics) is building **Oasis Auto Spa**, a car-wash/detailing business system. Three Claude Design prototypes are the **source of truth, followed "hyper in detail"**:
- **Operations / Command Center** — claude.ai/artifact/4u779LJgDvSgdsq7G59XnD (timeline, bay board, staff, calendar, appointment file with 8 tabs, new appointment/walk-in)
- **Payments** — claude.ai/artifact/GEYF4EjCGymd61DuGVt3nt (KPIs, chart, invoice table, ledger/audit trail, refund/adjust/credit/collect sheets, approvals)
- **Settings** — claude.ai/artifact/2Lsnk4xq9rDAz5PBGygFw3 (hours, holidays, emergency closing, employees, roles & 27 permissions with money limits, VIP, arrival, packages & checklists)

Scope: **dashboard + backend only** (customer app and public site come later; `~/oasis/site` untouched). Repos exist, empty, with deploy keys: `~/oasis/backend` (unielogics/OasisBackend), `~/oasis/dashboard` (unielogics/OasisDashboard), branch `main`. This plan supersedes `pasted-content-id-28ee-use-the-ancient-peacock.md` (blocked on DesignSync; the designs arrived as artifacts instead).

## What the designs turned out to be (findings from decoding all three)
- Each is a self-contained "dc" bundle: HTML template + `class Component extends DCLogic` script, React 18.3.1, 9 embedded woff2 fonts (Manrope, Bricolage Grotesque). **They run offline**, so we can render the originals headlessly as the pixel baseline.
- The template language is tiny and mechanical: `<sc-if>`, `<sc-for>`, `{{ident.path}}` only (all 1,075 expressions are plain paths, **no expressions**), inline styles + CSS-variable tokens, no media queries (fixed 1480×1000 desktop). Every derived label/colour/boolean is computed in `renderVals()`. ⇒ **a mechanical compile to TSX with identical DOM is feasible**, including the runtime's `span.sc-interp` wrapper spans and whitespace text nodes.
- They are static mocks: all fixtures, state and the only persistence (`localStorage` keys `oasis-*`) live in the script; many numbers are fabricated or hard-coded (e.g. "12 booked", "3.5h", `visits*148`, hash-based "affected" counts, "Rafael M." as the user, frozen date 2026-06-13/10:36). The backend must supply real rules for all of that.
- The three screens contradict each other in places (tax rounding whole-dollar vs cents, invoice-ID collisions in the fixtures, VIP/role/staff data, Support role can refund but cannot open Payments, emergency closure is only a banner in Operations…). 50 inconsistencies are catalogued; resolutions are below.

## Locked decisions (all from the user)
| Area | Decision |
|---|---|
| Stack | Next.js (TypeScript) dashboard; Node 22 + TypeScript API (Fastify); Postgres 15. Desktop-first, no mobile work. |
| Tenancy | Single location (one seeded row; every location-scoped table carries `location_id` so a 2nd location is a migration, not a rewrite). |
| Auth | Email + password (scrypt), httpOnly-cookie sessions, real RBAC from Settings. "Preview as" survives only as a Super-Admin "view as". |
| Money / time | Integer cents everywhere; 7% tax (setting) half-up to the cent; tip untaxed; Operations shows cents only when not whole. Business tz America/New_York, UTC storage. |
| Payments | **Squarespace stays the card processor.** Oasis owns the ledger and **syncs from Squarespace**; membership payments = Squarespace subscription products (user has a Commerce plan with API access). Card payments recorded by staff **count as Paid immediately, flagged "awaiting Squarespace"** until the feed/staff confirm. |
| Messaging | **SMS only**, via **SMS Gate on an Android tablet over the Tailscale tailnet**. Every "WhatsApp" label becomes "SMS", same layout. |
| Email / files | AWS SES; AWS S3 (private, presigned). No credentials yet: real adapters against sandboxes + built-in simulators; keys via env. |
| Access | Public HTTPS domain for the dashboard/API; SMS-tablet webhooks tailnet-only. |
| UI additions | Minimal, built only from the designs' own components, each listed in a deviations manifest the user can veto item by item. |

**Honest limits of Squarespace (verified against its docs):** the Commerce APIs read/import orders, read transactions (read-only), manage contacts, and send order webhooks (**webhooks need an OAuth app; API keys need Commerce Advanced**). They **cannot charge cards, refund, create payment links/invoices, expose saved cards, or manage Member Areas billing**; transactions expose a card *brand* enum, not last4. So "membership payments + card on file via API" is delivered as far as the API allows (below); the gaps and the fallback (connect your own Stripe account to Squarespace later, behind a `PaymentProcessor` seam) are documented, not hidden.

## Architecture

### Dashboard — "compile, don't redraw"
- **Next 15.x *Pages Router*, React/ReactDOM pinned 18.3.1** (App Router would silently use Next's vendored canary React and defeat the parity pin; fallback Next 14.2.x Pages). `reactStrictMode:false`; parity runs against `next build && next start`. Screens render client-only (`dynamic ssr:false`). Plain `<a>` links = full page loads, exactly like the originals, so each screen keeps its own global CSS (injected verbatim per page; **no Tailwind, no reset, no merged stylesheet** — the three helmet CSS blocks differ). `data-theme` stays on the wrapper div (also mirrored on `<html>`). Fonts self-hosted with the exact family names. Routes `/operations /payments /settings#section` (+`/login` etc.).
- `design/` = immutable reference (original bundles, extracted template/logic/fonts, checksums). **`tools/dc-compile`** (parse5 → TSX, build-time, output committed): scope stack for `sc-for`, `cssToObj` static styles in source order, `span.sc-interp` and whitespace text nodes preserved, `data-dc-tpl` numbering for node-by-node comparison, a **patch layer** for deviations with guards.
- **Logic layer:** keep each `DCLogic` class (typed facade / `@ts-nocheck` at first) behind a `DCHost` shim with the runtime's synchronous `setState`; stage 1 runs verbatim on fixtures (the parity oracle), stage 2 swaps fixtures/localStorage/clock for an API-backed data port + command layer, extracting pure helpers (`money`, `parseT`, `calc`, `lim`, …) with unit tests. 1 s tick, gesture engine (380 ms long-press, 6 px drag, ±90/150 px swipe, 450 ms click suppression), `elementFromPoint` drop targets, keyboard shortcuts preserved verbatim. A `renderVals` **provenance table** (server-supplied vs client-derived per key) is written before wiring.
- **Realtime:** SSE (`/api/events`, `Last-Event-ID` replay, heartbeats, `resync` event) feeding a query cache; 20–60 s poll fallback.
- **Permissions:** session carries the 27-key map + limits; locked/disabled states exactly as designed (Payments), existing-style toast elsewhere; server enforces everything.

### Backend (Fastify 5 + Zod/OpenAPI + Kysely/`pg` + pg-boss, no Redis)
- Modules: auth/rbac, settings (hours, rules, closures, emergency, VIP, arrival), people (employees/roles), catalog (+stable checklist task ids), customers/vehicles, scheduling (appointments, availability engine, bays, calendar, alerts, KPIs), jobs (checklist, photos, arrivals), payments (invoices, append-only ledger, credit, approvals, reports/CSV), memberships, messaging (SMS), integrations (ports + adapter + simulator each), notifications, realtime.
- Conventions: UUIDv7 ids; injectable `Clock` + SQL `app_now()` (bare `now()`/`Date.now()` banned, enforced by lint); RFC 9457 errors whose `title/detail` are the design's toast strings; `Idempotency-Key` on **every** money-effecting route (client generates it when the sheet opens); `expectedStatus` on `advance`; optimistic `version`; audit log insert-only; permission declared in route metadata and an authz-matrix test generated from the registry.
- Ledger: append-only `ledger_events` (pay/adjust/refund/credit_issue/credit_apply/void; refund `pending|done|denied`; `processor_state` for Squarespace) + an `invoice_calc` view that ports the Payments formulas exactly in cents (golden vectors: the 105-invoice set); store credit via **materialized FIFO allocations with expiry**; invoices created at booking, gap-free `INV-` numbers continuing from 20611.
- RBAC: union of roles; money limit = highest among roles that grant the permission, `null` = unlimited, **no row = $25**, units in cents; deny > allow > role; only Super may change limits / assign Super / grant `set.billing`/`pay.void`; last-Super protected; view-as evaluates as the viewed role, audited with the real actor.
- Availability engine (replaces the hard-coded slots): hours + closures + emergency + slot/buffer/cutoff (cutoff applies to the start time) + bay-capacity sweep-line + VIP holds with release window + same-day guarantee + permissioned override with reason; DB enforces one cleaning job per bay (partial unique index).

### Integrations (each = port + real adapter + simulator, chosen by `*_PROVIDER`)
| Integration | Design |
|---|---|
| **Squarespace** | **Polling is the baseline** (Orders incl. subscription orders, Transactions, Contacts API [Profiles is maintenance-mode]; cursor + overlap, ~2 min, 300 req/min limit) with OAuth webhooks as an optional accelerator. Matching: staff-recorded `awaiting_processor` event (same customer + amount within 48 h) → payment-link match → manual queue; never auto-confirm below threshold; store Squarespace totals + tax/fee variance; ingest out-of-band refunds as `source=squarespace` events with an alert. Card display = brand only ("Visa · managed in Squarespace"). Payment link = staff-attached Squarespace checkout/invoice URL sent by SMS (no query-token matching — it isn't stored on orders). Membership = product→tier map; status inferred from renewal orders + grace period (cancellations are lagged — documented). |
| **SMS Gate** | `SmsProvider` interface + SMS Gate adapter + simulator. Outbound HTTP to the tablet over the tailnet (Basic auth; our message id passed through; on timeout `GET /messages/{id}` before any re-send). Inbound/status via one webhook per event (`sms:received/sent/delivered/failed/cancelled`, `system:ping`, `app:started`), HMAC-SHA256 (`X-Signature`+`X-Timestamp`), HTTPS via `tailscale serve --set-path /hooks/smsgate` only. Single-device dispatcher: priority lanes (transactional reserved), token bucket **default ≤ 30 per 30 min until verified on the device** (Android's SMS prompt), TTL per class, GSM-7 normalisation, health polling + alert. STOP/START/HELP/C parsed **in Oasis**; unknown senders quarantined (no junk customers); synthetic-number + `SMS_ALLOWLIST` guard so seeds never text strangers. |
| **SES / S3** | SES v2 (receipts, invites, resets, alerts, SNS bounce handling, sandbox first). S3 presigned **POST** with size policy; HEIC rejected or converted client-side; thumbnails server-side. |

## Deliberate deviations from the designs (tracked in `design/deviations.yaml`; harness fails on anything unlisted)
- **D1** WhatsApp → SMS via an explicit string table (not find/replace: e.g. "WhatsApp, with SMS fallback" → "Sent by SMS"; "Preview · SMS to Liam"; "SMS opted-in"; "Receipt sent via SMS + email").
- **D2** fabricated/hard-coded numbers become real computations (KPIs, affected counts, renewal dates, card hint, current user, dates/clock); cc money strings show cents when non-whole.
- **D3** clear logic bugs fixed (inverted Added/Removed toast, singular/plural, "Today" divider, Ctrl+R advancing a job, un-pay bypassing the ledger, today never shown closed, self-approval of refunds, Deny with no permission check, over-cap message naming the wrong tender, etc.). Quirks that are visual (toast `oa-rise` jump, dark-mode fixed colours, unused keyframes, photo grid) are **replicated**.
- **D4** minimal new surfaces from existing primitives: login, invite-accept/set-password, forgot/reset, sign-out menu on the user chip, boot splash/error boundary, 403 toast + locked card for inaccessible screens.
- **D5** Squarespace/SMS states in existing elements: "Awaiting Squarespace" pill/ledger tag, "Confirm in Squarespace" button beside Approve/Deny, "Queued/Failed" on message bubbles, `SMS opted-out` chip, alert cards for device/sync failures.
- **D6** wiring-only additions (no visual change): editable New-Appointment fields, real message composer, photo upload tile + thumbnails, Squarespace-link URL input, `void` ledger row, "Other" payment-method row only when non-zero.
Manifest deviation types: `text`, `attr`, `reorder`, `element-added`, `region-mask`, `wiring`.

## Corrections folded in from the adversarial reviews (spec rules, not open questions)
- Milestone graph fixed: the **domain-core migration (customers, vehicles, bays, appointments, catalog) lands in M2, before Settings**; `design` seed data built incrementally per vertical.
- Two parity seed profiles: **`parity-ops`** (invoices for all 11 appointments, cent-level expected KPIs, e.g. pending $1,298.53) and **`parity-pay`** (the 105-invoice set), each run on a **separate parity DB + API instance with a frozen clock** (`2026-06-13T10:36:00-04:00`, explicit offset); Playwright `clock.install` → `pauseAt` → `runFor`; touch gestures via synthetic `PointerEvent`/CDP touch.
- Invoice rules: canceled-with-kept-deposit and no-show statuses handled; `biz_date` frozen at service/completion; "Revenue today" defined cash-basis (events occurring today); "N booked" sub-label = upcoming booked+confirmed; Bay-time-free and late rule (now > start+10 min) defined; Operations "Mark Paid" asks cash vs card (default last tender); add-on after payment re-opens a balance, removal that would overpay → 409; adjustment settlement refund is a normal refund event (card dest → awaiting processor); refund-by-item tracks item ids.
- Auth completeness: bootstrap admin (env/CLI), invite-accept requires email, admin-triggered SMS password reset, per-IP+account throttling (no 15-min lockout of a known email), `canViewAs` separate from effective authority, `cli.contact` redaction (also excluded from search), Settings page/section gating, pay rates redacted without `team.edit`.
- SMS policy layer: one `canSendSms(customer, purpose)`; quiet hours for non-transactional only; cellular-capable tablet with SIM is a hard precondition; Tailscale key expiry disabled on both nodes.
- Seeds: `/inspection/i` tasks dropped at seed time; invoice-ID collisions renumbered (generated history skips used ids); generated federal-holiday closures default `notify=false`; emergency link stripped until a reschedule landing page exists (`RESCHEDULE_LINK_ENABLED`).
