# Storage: AWS S3 (and the filesystem simulator)

Code: `src/integrations/storage/` (providers), `src/integrations/media/` (thumbnails). Port: `StorageProvider` (`createUpload`, `head`, `getDownloadUrl`, `delete`); both drivers also implement `ObjectStorage` (`get`, `put`) for the thumbnail job. Drivers are chosen by `STORAGE_PROVIDER=fs|s3` through `createStorageProvider(env, deps)`.

## Contract

| Item | Value |
|---|---|
| Key | `loc/{locationId}/appt/{apptId}/{category}/{photoId}.{ext}` via `buildPhotoKey`; category is `arrival`, `before`, `after` or `issue`; segments match `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`; extension comes from the validated content type. Thumbnail: `.../{photoId}.thumb.webp` (`thumbKeyFor`). |
| Allowed types | `image/jpeg`, `image/png`, `image/webp`. |
| HEIC / HEIF | **Rejected server-side** with `StorageError('HEIC_NOT_SUPPORTED')`: "HEIC/HEIF photos are not accepted by the server. Convert the photo to JPEG on the device before uploading ...". Also detected by magic bytes in the fs handler and the thumbnail validator. |
| Size | 1 byte to 15 MB (`MAX_UPLOAD_BYTES`), enforced by the signed POST policy (`content-length-range`). |
| Upload TTL | 5 minutes (`UPLOAD_TTL_SEC`); download TTL 10 minutes (`DOWNLOAD_TTL_SEC`). Any TTL outside 1 s to 1 h is refused. |
| Upload | Presigned **POST** (not PUT, which cannot cap size): browser sends `multipart/form-data` with every `slot.fields` entry first and the `file` part last, to `slot.url`. The fs driver speaks the same form, so the client code is identical. |
| Verification | After upload the app calls `head(key)` and checks `bytes` and `contentType` before committing the DB row. |
| Reads | `getDownloadUrl(key, 600)`: presigned GET, `response-content-disposition=inline`, `response-cache-control=private, max-age=<ttl>`. |

### HEIC and iPhone photos

The server never converts HEIC (sharp's prebuilt binaries have no HEVC decoder, and a conversion library would add a native dependency). To support iPhone photos, **convert in the browser before requesting the upload slot**: decode with `createImageBitmap` or an `<img>` element (Safari decodes HEIC natively; Chrome and Firefox need a WASM decoder such as `heic2any`/`libheif-js` loaded lazily only when `file.type` is `image/heic`, `image/heif` or the extension matches), draw to a canvas, `canvas.toBlob(cb, 'image/jpeg', 0.85)`, then send `contentType: 'image/jpeg'` and the converted size. Downscaling to about 2560 px on the long edge at the same time keeps most photos far below 15 MB. Alternative with no code: iOS Settings, Camera, Formats, Most Compatible. The API returns the clear HEIC message above if an unconverted file slips through, which the dashboard should show verbatim.

## Environment variables

`STORAGE_PROVIDER`, `STORAGE_FS_ROOT` (default `./.data/files`), `S3_BUCKET` (required for `s3`), `AWS_REGION`, `PUBLIC_API_URL`, and the
variables below, all declared in `src/config/env.ts` (the shape lives in `src/integrations/storage/env.ts` and is spread into
`envSchema`; ADR 0112). Credentials come from the AWS SDK default chain: in production the instance role `oasis-app-role`
(`pnpm aws:provision --runtime role`, the recommendation) or the `oasis-app` key in `/etc/oasis/aws-credentials` (`--runtime user`,
named by `AWS_SHARED_CREDENTIALS_FILE` with `AWS_EC2_METADATA_DISABLED=true`); see [../aws-setup.md](../aws-setup.md) and ADR 0133.

| Variable | Default | Meaning |
|---|---|---|
| `S3_KEY_PREFIX` | empty | Prefix inside the bucket (`prod/`, `staging/`) so one bucket can serve several environments. Applied on every call; callers only see the logical key. The signed POST policy pins the full key. |
| `S3_SSE` | `none` | `none` relies on the bucket's default encryption (SSE-S3 is on for all new buckets). `AES256` or `aws:kms` also sends and pins the `x-amz-server-side-encryption` field. |
| `S3_KMS_KEY_ID` | unset | KMS key ARN/ID when `S3_SSE=aws:kms`. |
| `S3_ENDPOINT`, `S3_FORCE_PATH_STYLE` | unset, `false` | Only for the AWS simulator (`scripts/verify-live/sim-aws.ts`) or S3-compatible stores such as MinIO. The photo flow and the thumbnail job run against the simulator with exactly these two set (test/aws/sim-e2e.test.ts). |
| `STORAGE_SIGNING_SECRET` | unset | HMAC key (16+ chars) for fs dev URLs. Falls back to `SESSION_SECRET`, then to a fixed dev value outside production; fs in production without either fails fast. |

## Filesystem simulator (`STORAGE_PROVIDER=fs`)

Objects live under `STORAGE_FS_ROOT/objects/<key>` with a content-type sidecar in `meta/`. Slots carry an HMAC-SHA256 signature over `(purpose, key, content type, max bytes, expiry)`; download URLs sign `(key, expiry)`. Purposes are domain-separated, comparisons are timing-safe, expiry is read from the injected `Clock`, and keys are validated against traversal.

Mount `createFsStorageHandler(provider, { allowOrigin: PUBLIC_DASHBOARD_URL })` under `/dev-storage/*`:

```ts
if (storage instanceof FsStorage) {
  const dev = createFsStorageHandler(storage, { allowOrigin: env.PUBLIC_DASHBOARD_URL })
  app.addContentTypeParser('multipart/form-data', { parseAs: 'buffer', bodyLimit: MAX_BODY_BYTES }, (_req, body, done) => done(null, body))
  app.all(`${DEV_STORAGE_PREFIX}/*`, async (req, rep) => {
    const r = await dev({ method: req.method, url: req.url, headers: req.headers, body: req.body as Buffer | undefined })
    rep.code(r.status).headers(r.headers).send(r.body)
  })
}
```

Endpoints: `POST /dev-storage/upload` (multipart, 204 on success like S3), `GET|HEAD /dev-storage/files/<key>?exp&sig`, `OPTIONS` preflight. The handler is stricter than S3 in one way: it sniffs magic bytes and refuses a file whose content does not match the signed content type (including HEIC), so simulator runs catch client bugs that S3 would store silently. Responses carry `nosniff`, a locked-down CSP and `no-store`. It never starts a stream it cannot finish (the file is opened before the 200 is sent).

## One-time AWS setup

**Use `pnpm aws:provision` ([../aws-setup.md](../aws-setup.md))**: it creates the photos bucket `oasis-photos-<acct>` with every setting
below (Block Public Access, BucketOwnerEnforced, SSE-S3, CORS for the dashboard origins, lifecycle, TLS-only policy), the backups bucket,
and the `oasis-app` policy scoped to the key prefix, plan first and idempotently. The manual steps explain what it does.

1. **Bucket** (private, one per environment; names are global):
   ```
   aws s3api create-bucket --bucket oasis-photos-<acct> --region us-east-1
   # outside us-east-1 add: --create-bucket-configuration LocationConstraint=<region>
   aws s3api put-public-access-block --bucket oasis-photos-<acct> --public-access-block-configuration \
     BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
   aws s3api put-bucket-ownership-controls --bucket oasis-photos-<acct> \
     --ownership-controls 'Rules=[{ObjectOwnership=BucketOwnerEnforced}]'
   ```
   Default encryption: new buckets already use SSE-S3. For KMS: `aws s3api put-bucket-encryption` with `aws:kms` and your key, then set `S3_SSE=aws:kms` and `S3_KMS_KEY_ID`.
   Recommended TLS-only bucket policy:
   ```json
   { "Version": "2012-10-17", "Statement": [{
       "Sid": "DenyInsecureTransport", "Effect": "Deny", "Principal": "*", "Action": "s3:*",
       "Resource": ["arn:aws:s3:::oasis-photos-<acct>", "arn:aws:s3:::oasis-photos-<acct>/*"],
       "Condition": { "Bool": { "aws:SecureTransport": "false" } } }] }
   ```
2. **CORS** (required: the browser POSTs straight to S3). Replace the origin with `PUBLIC_DASHBOARD_URL` (add `http://localhost:3000` only for a dev bucket):
   ```json
   { "CORSRules": [{
       "AllowedOrigins": ["https://dashboard.oasisautospa.example"],
       "AllowedMethods": ["POST", "GET", "HEAD"],
       "AllowedHeaders": ["*"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3000 }] }
   ```
   Apply: `aws s3api put-bucket-cors --bucket oasis-photos-<acct> --cors-configuration file://cors.json`. Presigned `<img src>` GETs need no CORS; the `GET` rule covers `fetch()` reads.
3. **IAM** for the app role (EC2 instance profile). Scope to the environment prefix:
   ```json
   { "Version": "2012-10-17", "Statement": [
     { "Sid": "Objects", "Effect": "Allow",
       "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
       "Resource": "arn:aws:s3:::oasis-photos-<acct>/prod/*" },
     { "Sid": "ListForHeadSemantics", "Effect": "Allow", "Action": "s3:ListBucket",
       "Resource": "arn:aws:s3:::oasis-photos-<acct>" } ] }
   ```
   `s3:ListBucket` matters (and carries no `s3:prefix` condition, because a HeadObject request has no `s3:prefix` to match, so a conditioned grant would not apply): per the AWS HeadObject documentation, a HEAD for a missing key returns 404 only when the caller has `s3:ListBucket`, otherwise 403. Without it `head()` would raise `PROVIDER_ERROR` instead of returning `null`, and a key that was never uploaded could not be told apart from an access problem. If you use SSE-KMS add `kms:GenerateDataKey` and `kms:Decrypt` on the key. Presigned URLs act with the signer's permissions, so the role needs `PutObject` (presigned POST) and `GetObject` (presigned GET). URLs signed with temporary role credentials stop working when those credentials expire; the SDK refreshes them early, and the 5 and 10 minute TTLs sit well inside a normal session.
4. **Lifecycle** (suggestion, subject to the retention decision): the plan keeps photos 24 months. Let the DB retention job soft-delete and enqueue S3 deletes; use a lifecycle rule as the backstop, set a little longer than the DB rule so the DB is always the one that decides:
   ```json
   { "Rules": [
     { "ID": "expire-photos-after-24-months", "Status": "Enabled", "Filter": { "Prefix": "prod/loc/" },
       "Expiration": { "Days": 760 } },
     { "ID": "abort-incomplete-uploads", "Status": "Enabled", "Filter": { "Prefix": "" },
       "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 1 } } ] }
   ```
   Apply with `aws s3api put-bucket-lifecycle-configuration`. (760 days is roughly 25 months; 24 months is 730 days if you want them identical.) Orphaned `pending_upload` objects (slot issued, `complete` never called) are removed by `photos.finalize` after 15 minutes; the lifecycle rule is only the last resort. If you enable versioning, add a `NoncurrentVersionExpiration`.
5. Set `STORAGE_PROVIDER=s3`, `S3_BUCKET`, `AWS_REGION`, `S3_KEY_PREFIX=prod/` in the environment. Credentials: the default AWS chain only.

## Media: thumbnails

`ThumbnailService` (`src/integrations/media/`) produces a WebP thumbnail with `sharp`, declared as an **optional** dependency and loaded lazily with try/catch. Sharp 0.35.5 prebuilt arm64 binaries load on this Amazon Linux 2023 aarch64 host (verified: version info printed and thumbnails generated in the tests). If it does not load anywhere else, `create()` returns `null` after validating the input, `available()` is `false`, and the dashboard serves the original. HEIC is rejected before sharp is involved.

- `validateImageInput(buf, { declaredType })`: pure; size cap, magic bytes, declared-type match, dimensions read from the header (JPEG SOF, PNG IHDR, WebP VP8/VP8L/VP8X) and a 40-megapixel limit, so a decompression bomb is refused before any decoder runs.
- `planThumbnail(info, { maxEdge = 480, quality = 78 })`: pure; `fit: inside` a square box, never enlarges, WebP, EXIF orientation applied, all metadata (GPS included) stripped.
- `generateAndStoreThumbnail(storage, service, key)`: job body for `photos.thumbnail`; reads the original, writes `{photoId}.thumb.webp`, and returns `created | skipped | invalid | missing` instead of throwing so the queue never retries a file that can never succeed.

pnpm note: sharp 0.35 ships its binaries as optional `@img/*` packages and needs no install script, so `pnpm.onlyBuiltDependencies` does not need to change. Run installs on the target architecture so the matching `@img/sharp-linux-arm64` package is selected.

## Verified against AWS documentation, and what is not

Verified: POST policy condition forms and the rule that every submitted field needs a matching condition (the test suite includes an evaluator that applies that rule to the signed policy); `content-length-range`; HeadObject permissions and the 403/404 behaviour; `createPresignedPost` source (conditions generated for every field, expiry computed from the real clock, no `signingDate` option).

Not verified against a live bucket (no credentials): a real browser POST against the CORS configuration above; lifecycle rule syntax was written from memory of the S3 API (check with `aws s3api put-bucket-lifecycle-configuration` and a dry look at the console); KMS permission set. The live check is `pnpm verify:aws --send` with the app's key (docs/aws-setup.md step 9). Presigned URLs always use the real wall clock (S3 validates request dates against its own), so a frozen `Clock` affects only the fs driver.
